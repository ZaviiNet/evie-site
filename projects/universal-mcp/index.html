Universal MCP addon platform

01The problem

One MCP server has to expose a large and growing tool surface without loading every addon's cost into every session.

Addon drift — an addon enabled but not loadable, or a tool count over the model's cap — had to be measurable rather than assumed, because the failure looks like a normal working server until a tool is missing.

02What I built

Per-addon directories behind a lazy-load proxy, an enabled-addons manifest, a router that mounts addons conditionally, and a test suite per addon family.

Inventory, tool-count ranking and budget checks turn the surface into numbers: what is enabled, what actually loaded, and how far the total sits from the cap.
