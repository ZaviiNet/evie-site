01The problem

The MCP 2.0 RC changed the protocol: stateless operation, tools/list TTL caching, server discovery, and a new method header. A scanner was built to find blockers — and a later session discovered the scanner itself was reporting incorrectly.

A false-clean is the same failure family as no audit at all: it converts an unknown into a wrong answer, which is harder to notice than silence.

02What I built

The scanner enumerates the protocol deltas across addon servers and separates blocking issues from warnings. A reality-check slice then corrected the scanner and added a paired liveness assertion, so the audit cannot pass on unread data.

Current measured claim: 63 addon servers scanned, 0 blocking issues, 9 warnings.
