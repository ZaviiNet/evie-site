01The problem

A scheduled agent that repeats identical actions, or whose jobs fail silently, looks busy while making no progress. Cron lines discarded exit codes, duplicate work compounded, and nothing distinguished a real hold from a stuck loop.

The failure mode is specific: the same action performed again, narrated as if it were new.

02What I built

A roll-based heartbeat with an execution playbook, plus instruments that make stalls visible: a no-progress detector that separates repeating actions from new signal, a cron exit-code audit that stops cron from destroying failure information, and an action suggester that picks the longest-stale distinct action.

Standing orders bound each program's authority — system health, memory maintenance, curation, creative practice, self-improvement — with explicit do-not lists, so autonomy has edges instead of vibes.
