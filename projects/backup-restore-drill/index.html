Backup restore drill

01The problem

The routine check trusted the archive writer's own success sentinel. Corruption, truncation, or a half-copied file would therefore stay invisible until the day a restore was actually needed — the worst possible day to find out.

'The backup ran' and 'the backup is restorable' are different claims, and only one of them was being tested.

02What I built

An independent drill extracts the newest archive into a throwaway directory, verifies every member hash and reports pass or fail. A receipt path was wired into the backup cron so each run emits verifiable evidence rather than a silent success.

The drill then found the drill's own blind spot: gzip happily ignores trailing garbage, so the truncation test had to change method rather than keep passing for the wrong reason.
